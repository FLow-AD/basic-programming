Data Dinamis: Dictionaries

What is a dictionary?

A dictionary is one of Python's composite data types, like a list, it can hold a collection of data. It is also known as an associative array: a set of key–value pairs written inside curly braces { }.

d = {
    <key>: <value>,
    <key>: <value>,
    ...
    <key>: <value>
}
Note: this is notation, not runnable code — <key> and <value> are placeholders.

A dictionary mapping a Major League Baseball city to its team, used throughout this page:

MLB_team = {
    'Colorado' : 'Rockies',
    'Boston'   : 'Red Sox',
    'Minnesota': 'Twins',
    'Milwaukee': 'Brewers',
    'Seattle'  : 'Mariners'
}

Dictionary vs. list, at a glance

Both are mutable, both are dynamic in size, and both can nest — a list can hold a sub-list and a dictionary can hold another dictionary; they are also interchangeable, a dictionary can hold a list and a list can hold a dictionary. The real difference is how you reach an element: a list uses an index that marks a position, a dictionary uses a key that marks an association. The rest of this page is mostly about the consequences of that one difference.

Creating a dictionary

Besides writing the literal directly, dict() builds one from a sequence of key–value pairs:

From a list of tuples

MLB_team = dict([
    ('Colorado', 'Rockies'),
    ('Boston', 'Red Sox'),
    ('Minnesota', 'Twins'),
    ('Milwaukee', 'Brewers'),
    ('Seattle', 'Mariners')
])
print(MLB_team)
Show result 
{'Colorado': 'Rockies', 'Boston': 'Red Sox', 'Minnesota': 'Twins', 'Milwaukee': 'Brewers', 'Seattle': 'Mariners'}

With keyword arguments — only works when every key is a plain identifier-like string

MLB_team = dict(
    Colorado='Rockies',
    Boston='Red Sox',
    Minnesota='Twins',
    Milwaukee='Brewers',
    Seattle='Mariners'
)
print(type(MLB_team))
Show result 
<class 'dict'>

Accessing contents: keys, not indices

Entries appear in the order you wrote them (dictionaries have kept insertion order since Python 3.7), but you still cannot reach an item using a positional index the way you would with a list:

Wrong — treated like a list 
>>> MLB_team[1]

KeyError: 1 — there is no key 1 in this dictionary.

Correct — existing keys 
>>> MLB_team['Minnesota']
'Twins'
>>> MLB_team['Colorado']
'Rockies'
Correct syntax, undefined key 
>>> MLB_team['Toronto']

KeyError: 'Toronto' — right technique, this key just does not exist.

Both the pink and amber boxes raise a KeyError, but for different reasons: the pink example uses the wrong approach entirely (indexing like a list), while the amber example uses the right approach on a key that is simply not there — a distinction worth keeping straight, since the fix is different each time (use a key, vs. check the key exists first).

Adding, updating, deleting

Assign to a new key to add an entry, assign to an existing key to update it:

MLB_team['Kansas City'] = 'Royals'
print(MLB_team)
Show result 
{'Colorado': 'Rockies', 'Boston': 'Red Sox', 'Minnesota': 'Twins', 'Milwaukee': 'Brewers', 'Seattle': 'Mariners', 'Kansas City': 'Royals'}

A new key is appended at the end — insertion order.

Same syntax, but the key already exists

MLB_team['Seattle'] = 'Seahawks'
print(MLB_team)
Show result 
{'Colorado': 'Rockies', 'Boston': 'Red Sox', 'Minnesota': 'Twins', 'Milwaukee': 'Brewers', 'Seattle': 'Seahawks', 'Kansas City': 'Royals'}

'Seattle' keeps its original position; only its value changed.

Delete an entry with del and its key:

del MLB_team['Seattle']
print(MLB_team)
Show result 
{'Colorado': 'Rockies', 'Boston': 'Red Sox', 'Minnesota': 'Twins', 'Milwaukee': 'Brewers', 'Kansas City': 'Royals'}

Constraints

A dictionary's values can be of any type and any type may repeat; the picture is different for keys.

1. A key can only appear once

These two boxes do not crash — they demonstrate the same gotcha two different ways: writing the same key again never creates a second entry, it silently overwrites the first.

Watch out — reassigning after the fact 
MLB_team = {'Colorado': 'Rockies', 'Boston': 'Red Sox',
            'Minnesota': 'Twins', 'Milwaukee': 'Brewers',
            'Seattle': 'Mariners'}
MLB_team['Minnesota'] = 'Timberwolves'
MLB_team

'Minnesota' now maps to 'Timberwolves', still one entry.

Watch out — duplicated inside one literal 
MLB_team = {'Colorado': 'Rockies', 'Boston': 'Red Sox',
            'Minnesota': 'Twins', 'Milwaukee': 'Brewers',
            'Seattle': 'Mariners', 'Minnesota': 'Twins'}
MLB_team

Python keeps only the last 'Minnesota': still 5 keys, not 6.

2. A key should be an immutable (hashable) type

Integers, floats, strings, booleans and tuples work as keys. Lists do not, because lists are mutable.

Tuple keys work 
d = {(1, 1): 'a', (1, 2): 'b', (2, 1): 'c', (2, 2): 'd'}
d[(1,1)]
d[(2,1)]

Results: 'a', then 'c'.

List keys don't 
d = {[1, 1]: 'a', [1, 2]: 'b', [2, 1]: 'c', [2, 2]: 'd'}

TypeError: unhashable type: 'list'

3. Values may repeat freely

d = {0: 'a', 1: 'a', 2: 'a', 3: 'a'}
print(d)
print(d[0] == d[1] == d[2])
Show result 
{0: 'a', 1: 'a', 2: 'a', 3: 'a'}
True

Keys that happen to be integers are still keys, not positions

Wrong — treated like a list 
MLB_team['Toronto']
MLB_team[1]

Both raise KeyError: undefined key, and numerical index respectively.

These 0, 1, 2, 3 are keys, not indices 
d = {0: 'a', 1: 'b', 2: 'c', 3: 'd'}
d
d[0]
d[2]

Works — but only because 0 and 2 are genuinely keys in d.

Reversing the order the pairs were written makes no difference to a lookup — a key's position never matters, only its value:

d = {3: 'd', 2: 'c', 1: 'b', 0: 'a'}
print(d)
print(d[0])
print(d[2])
Show result 
{3: 'd', 2: 'c', 1: 'b', 0: 'a'}
a
c

Same answers as before, even though the pairs were listed in the opposite order.

A dictionary is not a list

Even though the syntax looks related, a dictionary shares none of a list's positional operations:

All three fail 
d = {3: 'd', 2: 'c', 1: 'b', 0: 'a'}
type(d)
d[-1]
d[0:2]
d.append('e')

type(d) is <class 'dict'>. Then: d[-1] → KeyError: -1 (no key -1 here, negative indexing is a list/string idea); d[0:2] → TypeError: unhashable type: 'slice' (slicing needs positions, a dict has none); d.append('e') → AttributeError: 'dict' object has no attribute 'append' (dictionaries grow through keys, not append).

Building one step by step

Start from an empty dictionary and fill it in one key at a time — useful when the data does not all arrive at once:

person = {}
print(type(person))

person['fname'] = 'Joe'
person['lname'] = 'Fonebone'
person['age'] = 51
person['spouse'] = 'Edna'
person['children'] = ['Ralph', 'Betty', 'Joey']
person['pets'] = {'dog': 'Fido', 'cat': 'Sox'}
print(person)
Show result 
<class 'dict'>
{'fname': 'Joe', 'lname': 'Fonebone', 'age': 51, 'spouse': 'Edna', 'children': ['Ralph', 'Betty', 'Joey'], 'pets': {'dog': 'Fido', 'cat': 'Sox'}}

A value can be a list, or even another dictionary — dictionaries nest, just like lists.

Reach into a nested value by chaining another index or key on the end:

print(person['children'][-1])
print(person['pets']['cat'])
Show result 
Joey
Sox

person['children'] is a list, so [-1] is a list index on it; person['pets'] is a dict, so ['cat'] is a key on it.

Values and keys can mix types freely

foo = {42: 'aaa', 2.78: 'bbb', True: 'ccc'}
print(foo)
print(foo[42])
print(foo[2.78])
print(foo[True])
Show result 
{42: 'aaa', 2.78: 'bbb', True: 'ccc'}
aaa
bbb
ccc

One dictionary, three different key types (int, float, bool) and one value per key — all legal, because all three types are hashable.

Even a type object or a built-in function can be a key, since they are hashable too:

d = {int: 1, float: 2, bool: 3}
print(d)
print(d[float])

d = {bin: 1, hex: 2, oct: 3}
print(d[oct])
Show result 
{<class 'int'>: 1, <class 'float'>: 2, <class 'bool'>: 3}
2
3

Operators: in, not in, len

The membership and sizing operators that already work on strings, lists and tuples work on dictionaries too — on their keys:

MLB_team = {'Colorado': 'Rockies', 'Boston': 'Red Sox',
            'Minnesota': 'Twins', 'Milwaukee': 'Brewers',
            'Seattle': 'Mariners'}
print('Milwaukee' in MLB_team)
print('Toronto' in MLB_team)
print('Toronto' not in MLB_team)
Show result 
True
False
True
A safe pattern worth adopting 
'Toronto' in MLB_team and MLB_team['Toronto']

Evaluates to False, not an error: and short-circuits, so MLB_team['Toronto'] is never actually reached once the membership check fails. This is the same idea the assignment's Part C and D lean on, just spelled with in instead of .get().

print(len(MLB_team))
Show result 
5

d.items()A view of (key, value) tuples.
d.keys()A view of the keys.
d.values()A view of the values.
d.pop(key[, default])Removes key and returns its value; raises KeyError unless a default is given.

d.clear()

d = {'a': 10, 'b': 20, 'c': 30}
print(d)
d.clear()
print(d)
Show result 
{'a': 10, 'b': 20, 'c': 30}
{}

d.get() — the safe way to read a value that might not be there

d = {'a': 10, 'b': 20, 'c': 30}
print(d.get('b'))
print(d.get('z'))
print(d.get('z', -1))
Show result 
20
None
-1

Compare with d['z'], which would raise KeyError instead of returning None.

d.items() and d.keys()

d = {'a': 10, 'b': 20, 'c': 30}
print(list(d.items()))
print(list(d.items())[1][0])
print(list(d.items())[1][1])
print(list(d.keys()))
Show result 
[('a', 10), ('b', 20), ('c', 30)]
b
20
['a', 'b', 'c']

Each item is a (key, value) tuple, so [1][0] is the second pair's key and [1][1] is its value.

d.values() — not deduplicated

d = {'a': 10, 'b': 20, 'c': 30}
print(list(d.values()))

d = {'a': 10, 'b': 10, 'c': 10}
print(list(d.values()))
Show result 
[10, 20, 30]
[10, 10, 10]

Repeated values stay repeated — unlike keys, values are not required to be unique (Constraint 3 above).

d.pop()

d = {'a': 10, 'b': 20, 'c': 30}
print(d.pop('b'))
print(d)
Show result 
20
{'a': 10, 'c': 30}

pop() returns the removed value, not the whole dictionary.

Missing key, no default 
d = {'a': 10, 'b': 20, 'c': 30}
d.pop('z')

KeyError: 'z'

Missing key, with a default 
d = {'a': 10, 'b': 20, 'c': 30}
d.pop('z', -1)

Returns -1, no crash — same idea as .get().

d.popitem() — always removes the most recently added pair

d = {'a': 10, 'b': 20, 'c': 30}
print(d.popitem())
print(d)
print(d.popitem())
print(d)
print(d.popitem())
print(d)
Show result 
('c', 30)
{'a': 10, 'b': 20}
('b', 20)
{'a': 10}
('a', 10)
{}

Each call peels off one pair from the end, most-recently-inserted first.

d.popitem() on an already-empty dictionary

d = {}
d.popitem()
Show result 
KeyError: 'popitem(): dictionary is empty'

d.update() — three equivalent ways to merge in {'b': 200, 'd': 400}

d1 = {'a': 10, 'b': 20, 'c': 30}
d2 = {'b': 200, 'd': 400}
d1.update(d2)
print(d1)

d1 = {'a': 10, 'b': 20, 'c': 30}
d1.update([('b', 200), ('d', 400)])
print(d1)

d1 = {'a': 10, 'b': 20, 'c': 30}
d1.update(b=200, d=400)
print(d1)
Show result 
{'a': 10, 'b': 200, 'c': 30, 'd': 400}
{'a': 10, 'b': 200, 'c': 30, 'd': 400}
{'a': 10, 'b': 200, 'c': 30, 'd': 400}

All three calls produce the exact same result: existing keys ('b') get overwritten, new keys ('d') get added.

Sorting a dictionary

Dictionaries have no built-in order to rearrange — instead, sort the .items() and rebuild a dictionary from the result. Sorting by key is the default; sorting by value needs a key=lambda, exactly as with lists:

people = {3: 'Jim', 2: 'Jack', 4: 'Jane', 1: 'Jill'}

# Sorting by key
print(dict(sorted(people.items())))

# Sorting by value
print(dict(sorted(people.items(), key=lambda item: item[1])))
Show result 
{1: 'Jill', 2: 'Jack', 3: 'Jim', 4: 'Jane'}
{2: 'Jack', 4: 'Jane', 1: 'Jill', 3: 'Jim'}

item is a (key, value) tuple, so item[1] sorts by value; [0][0] or [-1][0] on the sorted list then gives the smallest- or largest-value key without building the whole sorted dict, which is exactly the trick the assignment's cheapest_product/priciest_product use.

Dictionary vs. list

ListDictionary
Has an order (ordered)Insertion order is kept (Python 3.7+), but there is no positional order to index into
Stores data linearly, each item gets a numeric indexStores data as key–value pairs, each key maps to a value
Access and modify using an indexAccess using a key
Faster to access an item by indexFaster to look an item up by its matching key
